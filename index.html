    C‑IDS User Guide

    What C‑IDS is and how the pieces fit together.

    C‑IDS is a modular, cross‑platform Intrusion Detection System core. The detection logic lives once, in C++, and every platform talks to it through a stable binary interface instead of keeping its own copy of the logic.

    HOW IT'S STRUCTURED

    1. 01 Core (C++20): parses traffic and matches it against detection rules behind a stable extern "C" boundary.
    2. 02 .NET bindings: a type‑safe P/Invoke layer wraps the core for Windows desktop apps, using SafeHandle for lifetime management.
    3. 03 Swift bindings: a Swift Package connects iOS apps to the core through a C module map and ships as an .xcframework.
    4. 04 Full architecture notes, the ABI contract, and the security policy live in the docs/ folder of the repository.

    QUICK START

    git clone https://github.com/aligokdam/c-ids.github.io.git
cd c-ids.github.io/C-IDS
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release \
      -DCIDS_ENABLE_HARDENING=OFF -DCLANG_TIDY_EXE=
cmake --build build
ctest --test-dir build/Core

    This builds the C++ core on Linux/macOS. Windows, .NET, and Swift build steps are covered in full in the repository's README.

    MODULE STATUS

    CORE

    C++ Engine

    A platform-independent detection engine, built on a zero-trust memory policy, RAII discipline, and a stable C ABI boundary.

    • › C++20 · header/impl separation
    • › no raw owning pointers
    • › ASan / UBSan verified
    .NET

    Desktop Bindings

    A type-safe P/Invoke layer for Windows. Wraps the native engine with SafeHandle discipline and never leaks a raw pointer.

    • › LibraryImport source-gen
    • › SafeHandle lifetime
    • › C# / .NET 8
    SWIFT

    Mobile Bindings

    A Swift Package for iOS. Connects to the core through a C module map, so application code never sees an unsafe pointer.

    • › Swift Package Manager
    • › .xcframework distribution
    • › iOS 15+

    Privacy

    Last updated: October 4, 2026

    This website is a static page. It has no accounts, no forms, no cookies, no analytics and no tracking scripts.

    The browser demo runs on your device

    The live demo is plain JavaScript that runs entirely in your browser. Traffic you paste or generate is analyzed locally, in memory. It is never sent to a server, never uploaded and never saved. Reloading or closing the page discards it.

    What is stored on your device

    Two preferences are kept in your browser's local storage so the page remembers them: your language (cids-lang) and your theme (cids-theme). They are not cookies and are not transmitted anywhere. You can remove them at any time by clearing this site's data in your browser.

    Third-party services

    The site is hosted on GitHub Pages, and its fonts are loaded from Google Fonts. To deliver those files, GitHub and Google receive standard technical request data such as your IP address and browser type, under their own privacy policies. Links to the GitHub repository take you to GitHub.

    The C-IDS libraries

    The C++ core and its .NET and Swift bindings are local libraries. The source code in the repository contains no telemetry and does not report data to the project. What an application built on C-IDS does with data is the responsibility of that application.

    Changes and contact

    If this notice changes, the update will appear on this page and in the repository history. Questions can be raised through the GitHub repository.
